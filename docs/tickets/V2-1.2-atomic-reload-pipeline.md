## Goal
Build the end-to-end data reload pipeline that unloads Parquet from Snowflake into a staging GCS prefix, validates file integrity, generates an updated snapshot manifest, and commits the snapshot into the PostgreSQL DuckLake catalog in a single atomic transaction.

## Acceptance Criteria
1. Script unloads Snowflake tables into `gs://scbi-ducklake-myanalyticsproduct/staging/<table_name>/<batch_id>/`.
2. Verifies file checksums and column counts against Snowflake source metrics before moving forward.
3. Generates new manifest entries in `ducklake_manifests` and executes an atomic SQL transaction updating `ducklake_snapshots.active_version`.
4. Moves or registers staging objects without leaving orphaned files or causing torn reads for ongoing queries.

## User Stories
1. *As an ETL pipeline operator*, I want reload jobs to stage data before updating catalog pointers, so that failed or interrupted reloads never corrupt live production tables.
2. *As a business analyst*, I want live dashboard queries to read consistent snapshots during ongoing batch reloads, so that my KPI reports never return half-loaded or duplicated counts.
3. *As a data engineer*, I want automated validation comparing Snowflake row counts to Parquet counts before commit, so that truncation or network drops are caught immediately.

## Seam
CLI execution test running a mock table reload against a staging bucket and verifying the transactional commit in PostgreSQL.
