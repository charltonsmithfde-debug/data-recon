## Goal
Implement the central security context inside Cube.js that parses inbound HS256 JWT claims, enforces compile-time role cube allowlists, and dynamically redacts sensitive personal data (POPIA compliance) using salted hashing for unauthorized roles.

## Acceptance Criteria
1. `security.js` extracts `role` and `canViewPii` from the verified JWT payload.
2. Inbound queries requesting cubes outside `ROLE_PERMISSIONS[role].allowedCubes` are rejected with HTTP 403 Forbidden.
3. Dimension fields flagged as PII (`id_number`, `member_id`, `client_name`) dynamically compile to salted hashes when `canViewPii === false`.
4. Password verification for SQL API callers uses secure scrypt hash comparison, rejecting forged credentials.

## User Stories
1. *As a compliance officer*, I want member IDs and personal identifiers masked at the database query level, so that unauthorized analysts cannot extract PII through the API or BI tools.
2. *As a security architect*, I want cube allowlists enforced at query compilation time, so that access restrictions cannot be bypassed by crafting direct GraphQL or REST query payloads.

## Seam
Jest unit test suite in Cube testing compile-time query rewrites for authorized vs unauthorized roles and masked vs unmasked fields.
