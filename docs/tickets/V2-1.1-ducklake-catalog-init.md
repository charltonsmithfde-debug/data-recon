## Goal
Initialize the PostgreSQL `ducklake_catalog` database schemas, manifest snapshot tracking tables, commit logs, and schema evolution tables in Cloud SQL / local PostgreSQL to serve as the single ACID metadata authority for DuckLake.

## Acceptance Criteria
1. DDL script `schema.sql` establishes `ducklake_snapshots`, `ducklake_manifests`, `ducklake_commits`, and `ducklake_tables`.
2. Python initialization script `init_catalog.py` idempotently applies schemas against a target PostgreSQL connection URL.
3. Successfully registers initial table metadata for all 44 migrated mart tables.
4. Provides verification query validating that snapshot pointers are queryable via standard SQL.

## User Stories
1. *As a data platform engineer*, I want an idempotent script to initialize the DuckLake catalog tables in PostgreSQL, so that metadata storage is reproducible across local and production environments.
2. *As an analytical query engine*, I want snapshot records stored with immutable transaction IDs, so that I can reliably execute snapshot-isolated queries without reading uncommitted data.
3. *As an auditor*, I want every commit logged with a timestamp, commit author, and affected table manifest, so that metadata history is fully auditable.

## Seam
PostgreSQL schema validation test executing `init_catalog.py` against test database and querying table catalog integrity.
