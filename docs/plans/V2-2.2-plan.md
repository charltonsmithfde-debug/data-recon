## 1. Architectural Scope & Contract

- **Goal**: Implement the central security context inside Cube.js (`version-two/cube/security.js`) that verifies inbound HS256 JWT tokens, extracts `role` and `canViewPii`, enforces compile-time role cube allowlists (rejecting unauthorized cubes with HTTP 403 Forbidden), dynamically redacts sensitive POPIA PII fields (`id_number`, `member_id`, `client_name`, `member_nk`) using salted SHA-256 hashing when `canViewPii === false`, and authenticates SQL API callers via constant-time `scrypt` password verification.
- **Role Roster Integration**: Reads `thin-web-app/role_assignments.json` (authoritative ADR-0003 roster) and enforces that `canViewPii` is governed strictly by `ROLE_PERMISSIONS[role].canViewPii && Boolean(claims.canViewPii)` so a non-PII role can never self-escalate PII visibility even if a token claim asserts `canViewPii: true`.

## 2. Step-by-Step Implementation Tasks

1. **Author `version-two/cube/security.js`**:
   - Define `ROLE_PERMISSIONS` covering V2 PRD roles (`ROLE_EXECUTIVE_ALL`, `ROLE_INVESTMENT_ANALYST`, `ROLE_ANNUITY_ANALYST`, `ROLE_MEMBER_OPERATIONS`, `ROLE_AUDIT_COMPLIANCE`) and V1 role identifiers (`ROLE_FINANCE_MEMBER`, `ROLE_INVESTMENTS`, `ROLE_ANNUITY`, `ROLE_DIGITAL_OPERATIONS`), plus `SHARED_DIMENSIONS`.
   - Implement HS256 JWT minting (`signHs256Jwt`) and verification (`verifyHs256Jwt`) + `checkAuth(req, auth)` extracting `role` and `canViewPii` from verified JWT claims and validating secret strength (>= 32 bytes, non-revoked).
   - Implement `queryRewrite(query, { securityContext })` enforcing `ROLE_PERMISSIONS[role].allowedCubes` (throwing a `ForbiddenError` with `statusCode = 403` and `httpStatus = 403` when an unauthorized cube is requested).
   - Implement dynamic POPIA PII masking helpers:
     - `PII_DIMENSIONS = ['id_number', 'member_id', 'client_name', 'member_nk']`
     - `compilePiiDimensionSql(columnExpr, securityContext, salt)` returning raw SQL `${columnExpr}` when `canViewPii === true` and `sha256(CAST(${columnExpr} AS VARCHAR) || '${salt}')` when `canViewPii === false`.
     - `maskRowPiiFields(row, securityContext, salt)` for result/compile-time redaction verification.
   - Implement SQL API authentication (`parseSqlUsers`, `scryptDigest`, `verifySqlPassword`, `checkSqlAuth`) using `crypto.scryptSync` and `crypto.timingSafeEqual`.
   - Implement `resolveUserRoleFromRoster(email, rosterPath)` reading `thin-web-app/role_assignments.json`.

2. **Wire `version-two/cube/cube.js`**:
   - Ensure HTTP server endpoint `/cubejs-api/v1/load` and `cube.js` exports integrate `security.js` hooks (`checkAuth`, `checkSqlAuth`, `queryRewrite`, `contextToAppId`, `compilePiiDimensionSql`) and return HTTP 403 when `queryRewrite` rejects an unauthorized cube.

3. **Author `version-two/tests/test_v2_2_2_cube_security_context.py`**:
   - **AC1 (`test_jwt_verification_extracts_role_and_can_view_pii`)**: Verifies HS256 JWT verification extracts `role` and `canViewPii`, rejects forged/tampered signatures, and prevents non-PII roles from escalating `canViewPii`.
   - **AC2 (`test_unauthorized_cube_rejected_with_http_403_forbidden`)**: Verifies `queryRewrite` and the HTTP `/cubejs-api/v1/load` endpoint reject queries outside `ROLE_PERMISSIONS[role].allowedCubes` with HTTP 403 Forbidden while allowing authorized cubes and `SHARED_DIMENSIONS`.
   - **AC3 (`test_popia_pii_dimensions_compile_to_salted_hashes`)**: Verifies `id_number`, `member_id`, and `client_name` dynamically compile to salted SHA-256 hashes when `canViewPii === false` and remain unmasked only when `canViewPii === true`.
   - **AC4 (`test_sql_api_scrypt_password_verification_rejects_forged_credentials`)**: Verifies `checkSqlAuth` and `verifySqlPassword` accept valid `scrypt` digests and reject wrong passwords, unknown users, and plaintext credential stores.
