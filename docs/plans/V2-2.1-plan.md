## 1. Architectural Scope & Contract

- **Goal**: Configure Cube.js 1.7.x (`@cubejs-backend/server: ^1.7.0`, `@cubejs-backend/duckdb-driver: ^1.7.0`, `@cubejs-backend/postgres-driver: ^1.7.0`) with embedded DuckDB via `@duckdb/node-api: ^1.2.1`, establishing startup attachment of the DuckLake catalog (`ATTACH 'ducklake:postgres:...' AS lake`) and enabling vectorized query execution over GCS.
- **Zero Deprecated Dependencies**: Removes legacy `0.35.0` packages and eliminates hardcoded `CREATE OR REPLACE VIEW ... read_parquet('s3://...')` SQL globbing.
- **Boot Sequence (`initSql`)**:
  - Dynamically loads `httpfs` and `ducklake` extensions (`INSTALL httpfs; LOAD httpfs; INSTALL ducklake; LOAD ducklake;`).
  - Sets `memory_limit = '3.5GB'` and `preserve_insertion_order = false`.
  - Attaches the DuckLake catalog as `lake` (`ATTACH 'ducklake:postgres:...' AS lake;`).
- **Embedded Driver & Local Catalog Seam**:
  - Provides `EmbeddedDuckLakeDriver` in `version-two/cube/cube.js` implementing Cube's `driverFactory` contract (`query(sql, params)`, `testConnection()`, `release()`).
  - Supports in-process `@duckdb/node-api` execution in production and deterministic DuckLake catalog resolution against the initialized catalog (`ducklake_tables`, `ducklake_manifests`, `ducklake_snapshots`) via `node:sqlite` for local/CI verification without external cloud network dependencies.
  - Exposes a local HTTP health/readiness server on port `4000` (`/readyz`, `/health`, `/cubejs-api/v1/meta`) that verifies catalog attachment and reports healthy status.

## 2. Step-by-Step Implementation Tasks

1. **Author `version-two/cube/package.json`**:
   - Specify Cube 1.7.x packages (`@cubejs-backend/server`, `@cubejs-backend/duckdb-driver`, `@cubejs-backend/postgres-driver` at `^1.7.0`) and `@duckdb/node-api` (`^1.2.1`).
   - Add `scripts` (`start`, `dev`, `test`) and `engines` (`node >= 20.0.0`).

2. **Author `version-two/cube/cube.js`**:
   - Implement `buildDuckLakeInitSql(env)` producing the exact DuckDB startup SQL (`INSTALL httpfs; LOAD httpfs; INSTALL ducklake; LOAD ducklake; ... ATTACH 'ducklake:postgres:...' AS lake;`) with zero hardcoded secrets.
   - Implement `EmbeddedDuckLakeDriver` binding in-process DuckDB (`@duckdb/node-api`) and resolving `lake.<schema>.<table>` queries against the DuckLake catalog (`ducklake_tables` / `ducklake_manifests` / `ducklake_snapshots`).
   - Export Cube 1.7.x server configuration (`dbType: 'duckdb'`, `driverFactory`, `http: { port: 4000 }`, `contextToAppId`, and CLI `--serve` / `--verify-query` entrypoints).

3. **Author `version-two/tests/test_v2_2_1_cube_semantic_engine.py`**:
   - **AC1 (`test_package_json_cube_1_7_and_duckdb_node_api`)**: Verifies `version-two/cube/package.json` specifies Cube `^1.7.x` and `@duckdb/node-api`, with zero `0.35` or deprecated dependencies.
   - **AC2 (`test_cube_js_init_sql_loads_httpfs_and_ducklake`)**: Verifies `buildDuckLakeInitSql()` installs/loads `httpfs` and `ducklake` and attaches `ducklake:postgres:... AS lake` without globbing views or hardcoded secrets.
   - **AC3 (`test_driver_executes_annuity_quotations_count_query`)**: Initializes the DuckLake catalog and executes `SELECT count(*) FROM lake.scbi_cdp_mart.cnf__fact_annuity_quotations` directly through the Cube driver (`driverFactory()`), asserting `188,832` rows returned from Snapshot `v1`.
   - **AC4 (`test_server_starts_cleanly_on_port_4000_and_reports_healthy`)**: Starts the Cube HTTP server on port `4000` (with fallback ephemeral port check if 4000 is occupied), queries `/readyz`, and verifies HTTP 200 `status: "HEALTHY"`.
