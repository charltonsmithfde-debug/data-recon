## 1. Architectural Scope & Contract

- **Goal**: Rewire Metabase and Power BI DirectQuery connections to point exclusively at the Cube SQL API (Postgres Wire Protocol on port `5432`, host `scbi-cube-sql`), prohibiting direct access to Cloud SQL (`scbi-ducklake-catalog`) or raw GCS storage (`gs://scbi-ducklake-myanalyticsproduct`) and documenting the IAP TCP tunneling procedure ([`ADR-0004`](../adr/0004-dual-delivery-topologies.md)).
- **Zero Bypass Enforcement**: BI connections must authenticate using scrypt-verified SQL API credentials (`checkSqlAuth`) and resolve queries strictly against Cube semantic models (`AnnuityQuotation`, `InvestmentAnalysis`, `MemberAnalysis`, `SharedDimensions`). Any direct query targeting `ducklake_*` catalog tables or raw `scbi_cdp_mart.*` storage paths is blocked with HTTP/SQL `403`.

## 2. Step-by-Step Implementation Tasks

1. **Author `version-two/metabase/setup.py`**:
   - Provide `build_metabase_cube_sql_datasource()` constructing the canonical Metabase `postgres` engine configuration pointing at `scbi-cube-sql:5432` (database `cube`, internal VPC peering) with scrypt-authenticated service account credentials read from environment variables (`METABASE_CUBE_SQL_USER`, `METABASE_CUBE_SQL_PASSWORD`).
   - Provide `validate_no_storage_bypass(datasource_config)` rejecting any Metabase datasource pointing directly at Cloud SQL (`5433` / `ducklake_catalog`), Snowflake, or raw GCS/DuckDB files.
   - Provide `build_powerbi_iap_tunnel_command()` generating the deterministic `gcloud compute start-iap-tunnel scbi-cube-sql 5432 --local-host-port=localhost:5432 --zone=europe-west1-b --project=myanalyticsproduct` command and connection metadata.
   - Provide `CubeSqlWireClient` (TCP socket client over port `5432`) that executes schema reflection (`SELECT * FROM information_schema.tables`, `SELECT * FROM information_schema.columns`), semantic metric queries (`SELECT COUNT(*) FROM AnnuityQuotation`, `SELECT totalAua, activeMemberCount FROM MemberAnalysis`), and verifies that direct storage bypass queries are blocked.

2. **Author `docs/METABASE_CUBE_SQL.md`**:
   - Step-by-step connection guide covering:
     1. Internal VPC Peering setup for Metabase -> `scbi-cube-sql:5432`.
     2. Scrypt credential provisioning (`CUBEJS_SQL_USERS` in Google Secret Manager).
     3. Power BI DirectQuery via Google Cloud IAP TCP Tunnel (`gcloud compute start-iap-tunnel scbi-cube-sql 5432`).
     4. Governed semantic SQL query patterns (`MEASURE(...)`) and POPIA masking guarantees.

3. **Author `version-two/tests/test_v2_3_3_downstream_bi_rewire.py`**:
   - Test AC 1: Metabase datasource configuration targets `scbi-cube-sql:5432` with scrypt-authenticated service credentials and rejects direct Cloud SQL / GCS bypass configs.
   - Test AC 2: Power BI DirectQuery IAP tunnel command (`gcloud compute start-iap-tunnel scbi-cube-sql 5432`) and PostgreSQL wire SSL negotiation (`SSLRequest` -> `'N'`) verified.
   - Test AC 3: Live TCP port `5432` SQL API integration test verifying schema reflection (`information_schema.tables`), semantic metric execution (`AnnuityQuotation`, `MemberAnalysis`, `InvestmentAnalysis`), RBAC enforcement, and rejection of direct `scbi_cdp_mart.*` / `ducklake_tables` bypass queries.
   - Test AC 4: Verifies completeness of `docs/METABASE_CUBE_SQL.md`.
