## 1. Architectural Scope & Contract

- **Upstream Dependency**: `version-two/ducklake/init_catalog.py` (`CatalogConnection` and v1 catalog schema).
- **Core Problem Solved**: Eliminates torn reads and stale-file double counting (ADR-0001 §1.2) by staging reloads into version-isolated GCS prefixes (`gs://.../staging/<schema>/<table>/v<N>/`) and switching active pointers via a single ACID transaction in `ducklake_catalog`.
- **Failure Isolation**: Any validation failure or database error triggers a full transaction rollback, leaving the previous snapshot active and untouched.

## 2. Step-by-Step Implementation Tasks

1. **Author `version-two/ducklake/reload_pipeline.py`**:
   - `StageTablePayload`: Data structure representing a staged table unload (`table_id`, `staged_gcs_uri`, `row_count`, `byte_size`, `expected_rows`, `checksum`).
   - `validate_staged_payloads(payloads)`: Verifies non-empty row counts, positive byte sizes, and exact match against `expected_rows` before opening a catalog transaction.
   - `commit_reload_batch(payloads, db_url, author, notes)`:
     - Determines `next_version = max(version_id) + 1`.
     - Executes within an atomic transaction:
       - Inserts `ducklake_snapshots` record for `next_version`.
       - Inserts new `ducklake_manifests` entries for all updated tables, while carrying forward manifest entries for unchanged tables so every snapshot is a complete, self-contained lakehouse view.
       - Updates `ducklake_tables.active_version = next_version` for affected tables.
       - Inserts audit record in `ducklake_commits`.
   - `resolve_table_snapshot(table_id, version_id=None, db_url=None)`: Resolves the exact manifest URI and row count for either the active snapshot or any historical `version_id` (time-travel).
   - `rollback_to_snapshot(target_version_id, db_url=None)`: Atomically repoints `ducklake_tables.active_version` back to a prior committed snapshot.

2. **Author `version-two/tests/test_v2_1_2_reload_pipeline.py`**:
   - Test 1 (`test_atomic_reload_creates_v2_snapshot`): Verifies staging and committing a reload advances snapshot from v1 to v2 and updates manifest URIs.
   - Test 2 (`test_precommit_validation_blocks_corrupt_stage`): Verifies mismatched row counts or 0-byte unloads raise `ReloadValidationError` and keep v1 untouched.
   - Test 3 (`test_time_travel_and_snapshot_isolation`): Verifies querying `version_id=1` returns v1 state while active queries return v2 state.
   - Test 4 (`test_instant_snapshot_rollback`): Verifies `rollback_to_snapshot(1)` restores v1 across all tables atomically.
