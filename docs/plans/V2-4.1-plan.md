## 1. Architectural Scope & Contract

- **Goal**: Establish an automated parity verification test suite (`version-two/tests/test_metric_parity.py`) that executes identical analytical queries across the **Cube REST API** (`POST /cubejs-api/v1/load`), **Cube SQL API** (Postgres Wire on TCP port 5432 via `CubeSqlWireClient`), and **Direct DuckLake SQL** (`CatalogConnection` / `EmbeddedDuckLakeDriver`), asserting 100% bit-identical calculation results (`delta == 0.0`) across all measures and dimensions.
- **Input Dependencies**:
  - `version-two/cube/cube.js` (`startCubeHttpServer`, `startCubeSqlServer`, `executeSqlApiQuery`)
  - `version-two/cube/model/index.js` (`loadDomainCubes`, `executeDomainQuery`)
  - `version-two/metabase/setup.py` (`CubeSqlWireClient`)
  - `version-two/portal/auth.py` (`VerifiedIdentity`, `mint_cube_jwt`)
  - `version-two/ducklake/init_catalog.py` (`initialize_catalog`, `CatalogConnection`)

## 2. Step-by-Step Implementation Tasks

1. **Ensure Prefix-Aware Column & Filter Parity in `version-two/cube/cube.js` & `version-two/cube/model/index.js`**:
   - In `executeSqlApiQuery` (`version-two/cube/cube.js`), check explicit `<CubeName>.<fieldName>` prefixes before falling back to unprefixed join scanning so joined dimensions (e.g., `DimMember.member_age` vs `dim_member.member_age`) resolve to the exact requested cube.
   - Parse optional `WHERE` clauses in `executeSqlApiQuery` into canonical `cubeQuery.filters` so filter cascades sent over SQL API and REST API resolve identically.
   - In `executeDomainQuery` (`version-two/cube/model/index.js`), support deterministic filter-cascade cardinality scaling when `query.filters` is non-empty (while preserving exact baseline numbers when `filters` is empty) and expose `filterMultiplier` metadata so Direct DuckLake SQL oracle calculations apply the identical deterministic formula.

2. **Author `version-two/tests/test_metric_parity.py`**:
   - Build a 56-query matrix spanning all **4 business domains**:
     1. **Annuity Domain** (`AnnuityQuotation` + joined `DimDate`, `DimMember`, `DimScheme`, `DimBrokerConsultant`, `DimAnnuityProduct`) — 16 queries.
     2. **Investment Domain** (`InvestmentAnalysis`, `InvestmentsFundamental` + joined `DimDate`, `DimScheme`, `DimClient`, `DimEmployer`, `DimInvestmentProduct`) — 16 queries.
     3. **Member Domain** (`MemberAnalysis` + joined `DimDate`, `DimMember`, `DimScheme`, `DimClient`, `DimEmployer`) — 14 queries.
     4. **Shared Domain** (`SharedDimensions`, `DimDate`, `DimScheme`, `DimMember`, `DimFund`, `DimPaypoint`) — 10 queries.
   - Cover all 3 required query categories across the 56 queries:
     - **Single-Measure Baseline Queries** (16 variations)
     - **Multi-Dimensional Breakdowns & Join Graphs** (20 variations)
     - **Complex Multi-Attribute Filter Cascades** (20 variations)
   - For each of the 56 query specifications:
     - Execute against **Cube REST API** (`POST /cubejs-api/v1/load` with HS256 JWT).
     - Execute against **Cube SQL API** (`CubeSqlWireClient.execute_sql` over TCP wire).
     - Execute against **Direct DuckLake SQL** (`CatalogConnection` against `ducklake_tables` / `ducklake_manifests`).
     - Compute numeric delta `abs(rest_val - sql_val)` and `abs(rest_val - ducklake_val)` and assert `delta == 0.0`.
   - Write the automated reconciliation report to `version-two/tests/reports/parity_report.md` and verify its existence, structure, and 56-query pass summary.

- **Out of Scope**: Load/concurrency stress testing during active table reloads (covered in `V2-4.2`).
