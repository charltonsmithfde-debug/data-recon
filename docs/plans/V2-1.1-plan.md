## 1. Architectural Scope & Contract

- **Input Source**: `scripts/migration_state.json` (authoritative registry of the 44 migrated mart tables, row counts, byte sizes, and GCS prefixes).
- **Database Target**: PostgreSQL 16 (`ducklake_catalog` via `DUCKLAKE_DB_URL` environment variable) with SQLite/in-memory compatibility mode for isolated unit testing when a live PostgreSQL server is not attached.
- **Idempotency Invariant**: Executing `init_catalog.py` multiple times against the same database must be completely idempotent (`CREATE TABLE IF NOT EXISTS`, `ON CONFLICT DO UPDATE`).

## 2. Step-by-Step Implementation Tasks

1. **Author `version-two/ducklake/schema.sql`**:
   - Define `ducklake_snapshots`: Tracks atomic lakehouse versions (`version_id`, `committed_at`, `author`, `status`, `notes`).
   - Define `ducklake_tables`: Tracks registered mart tables (`table_id`, `schema_name`, `table_name`, `gcs_prefix`, `active_version`, `row_count`, `output_bytes`, `updated_at`).
   - Define `ducklake_manifests`: Tracks exact immutable Parquet file paths belonging to a snapshot (`manifest_id`, `table_id`, `version_id`, `file_uri`, `row_count`, `byte_size`, `created_at`).
   - Define `ducklake_commits`: Audit trail of transactional commits (`commit_id`, `version_id`, `operation`, `tables_affected`, `committed_at`).

2. **Author `version-two/ducklake/init_catalog.py`**:
   - Parse `DUCKLAKE_DB_URL` from environment (no hardcoded credentials).
   - Load and execute `schema.sql` idempotently.
   - Read `scripts/migration_state.json` and seed initial snapshot `version_id = 1`.
   - Upsert all 44 tables into `ducklake_tables` and create corresponding initial manifest entries in `ducklake_manifests`.
   - Implement `verify_catalog()` returning table count, active snapshot version, total rows, and schema health status.

3. **Author `version-two/tests/test_v2_1_1_catalog_init.py`**:
   - Test 1: Schema creation and idempotency (run twice, verify table counts remain exact).
   - Test 2: Verify all 44 tables from `scripts/migration_state.json` are registered with accurate row counts and GCS paths.
   - Test 3: Verify active snapshot `v1` is committed and queryable.
   - Test 4: Verify zero hardcoded credentials in `version-two/ducklake/`.

## 3. Validation Plan (`de-validate`)
- **Syntax & Lint**: `python3 -m py_compile version-two/ducklake/init_catalog.py`
- **Unit & Contract Suite**: `python3 -m pytest version-two/tests/test_v2_1_1_catalog_init.py -v`
- **Representative Dry Run**: Run `python3 version-two/ducklake/init_catalog.py --verify` and inspect JSON verification output.

## 4. Rollback Plan
- Drop tables `ducklake_manifests`, `ducklake_tables`, `ducklake_commits`, `ducklake_snapshots` or remove `version-two/ducklake/`.

## 5. Out of Scope
- Live Snowflake data unloading (covered in `V2-1.2`).
- Docker Compose container orchestration (covered in `V2-1.3`).
