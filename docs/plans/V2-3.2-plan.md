## 1. Architectural Scope & Contract

- **Goal**: Replace the monolithic legacy `thin-web-app/server.py` (which contained hardcoded synthetic member numbers and mixed HTTP routing with auth) with a clean, decoupled API Gateway (`version-two/portal/auth.py` and `version-two/portal/server.py`) per [`ADR-0003`](../adr/0003-jwt-rbac-popia-masking.md) and [`ADR-0004`](../adr/0004-dual-delivery-topologies.md).
- **Zero Synthetic Endpoints**: `handle_member_analysis_query` and all analytical portal endpoints (`/api/member_analysis_query`, `/api/annuity_query`, `/api/investment_query`, `/api/cube/load`) proxy live queries to the Cube 1.7.x REST API (`/cubejs-api/v1/load`) with a freshly minted HS256 JWT derived strictly from server-side identity verification.

## 2. Step-by-Step Implementation Tasks

1. **Author `version-two/portal/auth.py`**:
   - Parse and validate the Google Cloud IAP header `X-Goog-Authenticated-User-Email` (e.g., `accounts.google.com:user@domain.com` -> `user@domain.com`), rejecting missing, blank, or malformed headers with HTTP `401 Unauthorized` (`AuthenticationError`).
   - Resolve the verified email against `thin-web-app/role_assignments.json`, falling back to least-privileged `ROLE_FINANCE_MEMBER` with `can_view_pii: False` for unknown corporate users, and ignoring any client-supplied `role` or `can_view_pii` query/body parameters.
   - Implement RFC 7518 compliant HS256 JWT minting (`mint_cube_jwt`) using Python standard library `hmac` + `hashlib.sha256` (requiring `CUBEJS_API_SECRET` >= 32 bytes) with claims `{sub, email, role, canViewPii, can_view_pii, iat, exp}`.

2. **Author `version-two/portal/server.py`**:
   - Provide a modular `APIRouter` + `FastAPI` application (`create_portal_app`) with routes:
     - `GET /health` & `GET /readyz`: Gateway health check.
     - `GET /api/whoami`: Returns the server-resolved identity (`email`, `role`, `can_view_pii`) from IAP header verification.
     - `GET /api/member_analysis_query` (`handle_member_analysis_query`): Replaces legacy synthetic data with live Cube REST API queries against `MemberAnalysis` (`MemberAnalysis.activeMemberCount`, `MemberAnalysis.averageMemberAge`, `MemberAnalysis.gender`, `MemberAnalysis.id_number`), returning `data_source: "cube_rest_live"` and `demo_data: False`.
     - `POST /api/cube/load`: Authenticated proxy endpoint forwarding semantic queries to Cube REST `/cubejs-api/v1/load` with the caller's minted HS256 Bearer token.
   - Include a built-in ASGI/HTTP `PortalTestClient` and `ThreadingHTTPServer` runner so automated tests and local servers run cleanly even in environments without third-party `uvicorn`/`httpx` wheels installed.

3. **Author `version-two/tests/test_v2_3_2_portal_api_gateway.py`**:
   - Test AC 1: Modular router structure (`auth.py` + `server.py`) with zero synthetic hardcoded fallbacks.
   - Test AC 2: `X-Goog-Authenticated-User-Email` parsing and HTTP `401` rejection for unauthenticated requests.
   - Test AC 3: Server-side role lookup from `role_assignments.json`, privilege escalation prevention (client `role` parameter ignored), and HS256 JWT minting verified by Node `version-two/cube/security.js`.
   - Test AC 4: Live end-to-end proxy test from `version-two/portal/server.py` (`handle_member_analysis_query` and `/api/cube/load`) to a running `version-two/cube/cube.js` HTTP server, verifying live `MemberAnalysis` data (`29,209,326` active member records) and POPIA masking.
